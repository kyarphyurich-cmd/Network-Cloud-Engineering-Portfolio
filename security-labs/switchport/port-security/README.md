# 🔐 스위치 포트 보안 실습 — 액세스 계층의 보안 정책 적용 및 복구

## 개요

이 실습에서는 Layer 2 스위치 한 대와 여러 단말을 사용하여 **액세스 계층의 포트 보안(Port Security)**을 검증합니다.

MAC 주소 기반 접근 제어, **보안 위반 모드(Violation Mode)**별 동작 차이, 원인을 해결하지 않은 포트 복구가 반복적인 통신 장애로 이어지는 과정을 확인합니다.

주요 학습 내용은 다음과 같습니다.

- 액세스 계층에서의 포트 보안 동작
- 보안 정책과 서비스 가용성 사이의 관계
- err-disabled 상태의 포트 문제 해결
- 원인 → 결과 → 검증 과정의 명확한 기록

보안 정책은 **Layer 2**에서 적용되며, 라우팅이나 상위 계층의 접근 제어는 사용하지 않습니다.

## 네트워크 구성 요약

### 장비

- **L2-SW-Access** — Layer 2 액세스 스위치
- **PC1** — VPCS
- **Linux-PC2** — Alpine Linux
- **PC3** — VPCS

### 도구 선택 이유

이 실습에서는 MAC 주소를 직접 변경하는 테스트에 Alpine Linux 호스트를 사용했습니다.

---

### VLAN 설계

- **VLAN 10** — 사용자 액세스 VLAN
- **서브넷** — `192.168.10.0/24`

### IP 주소

| 호스트 | IP 주소 |
|---|---|
| PC1 | 192.168.10.10 |
| Linux-PC2 | 192.168.10.20 |
| PC3 | 192.168.10.30 |

### 스위치 포트 연결

| 포트 | 연결 장비 |
|---|---|
| Gi0/0 | PC1 |
| Gi0/1 | Linux-PC2 |
| Gi0/2 | PC3 |

위 세 포트는 모두 **VLAN 10의 액세스 포트**로 설정했습니다.

## 1단계 — 기본 연결 확인: 보안 설정 전

### 목표

보안 기능을 적용하기 전에 호스트 간 Layer 2 연결이 정상적으로 동작하는지 확인합니다.

### 수행 내용

- Gi0/0, Gi0/1, Gi0/2를 VLAN 10에 할당
- 모든 호스트에 정적 IP 주소 설정
- PC1, Linux-PC2, PC3 간 통신 확인

### 검증 결과

- 모든 호스트 간 ICMP 통신 성공
- MAC 주소 테이블(CAM 테이블)에 호스트의 MAC 주소가 동적으로 학습됨
- 포트 보안 기능은 비활성화 상태

이 단계의 결과를 이후 보안 기능 적용 전후를 비교하기 위한 기준으로 사용했습니다.

## 2단계 — Sticky MAC 학습

### 목표

Sticky MAC 학습을 통해 동적으로 학습한 MAC 주소를 보안 MAC 주소로 등록하고, 포트 접근을 제한하는 동작을 확인합니다.

### 수행 내용

- Gi0/0에서 포트 보안 활성화
- **Sticky MAC 학습** 활성화
- PC1에서 트래픽 발생

### 관찰 결과

- 스위치가 PC1의 MAC 주소를 동적으로 학습했습니다.
- 학습된 MAC 주소가 실행 중인 설정인 `running-config`에 추가되었습니다.
- 이 실습 환경에서는 MAC 주소 테이블에 해당 주소가 **STATIC**으로 표시되었습니다.
- 인터페이스는 `secure-up` 상태를 유지했습니다.

### 검증 방법

다음 정보를 함께 확인했습니다.

- 포트 보안 상태
- running-config
- MAC 주소 테이블

### 핵심 내용

Sticky MAC 학습은 트래픽에서 확인한 MAC 주소를 보안 MAC 주소로 등록합니다.

이 실습에서는 허용 MAC 주소 수가 1개인 상태에서 PC1의 MAC 주소가 학습되어, 해당 포트의 접근이 제한되었습니다.

MAC 주소 테이블에 **STATIC**으로 표시되더라도, 해당 주소는 직접 입력한 것이 아니라 Sticky 기능으로 동적으로 학습한 주소입니다.

> Sticky MAC 주소는 running-config에 추가됩니다. 재부팅 후에도 유지하려면 설정을 startup-config에 저장해야 합니다.

```cisco
copy running-config startup-config
```

## 3단계 — 포트 보안 위반 모드 비교

인가되지 않은 MAC 주소가 나타났을 때 각 **위반 모드**가 트래픽 차단, 위반 확인, 서비스 가용성에 미치는 영향을 비교했습니다.

### 테스트 환경

- Gi0/1에서 포트 보안 및 Sticky MAC 학습 활성화
- Linux-PC2를 Gi0/1에 연결
- 정상 상태의 통신 확인

Linux-PC2의 MAC 주소를 다음과 같이 변경했습니다.

**변경 전**

```text
0c:42:e2:c7:00:00
```

**변경 후**

```text
00:11:22:33:44:55
```

---

### 3.1 Protect 모드 — 로그 없이 차단

#### 예상 동작

- 인가되지 않은 출발지 MAC의 트래픽 폐기
- 포트 보안 위반 로그 및 위반 카운터 증가 없음
- 인터페이스는 활성 상태 유지

#### 관찰 결과

- MAC 주소 변경 후 ICMP 통신 실패
- 인터페이스는 활성 상태 유지
- 포트 보안 위반 로그가 생성되지 않음

#### 결론

Protect 모드는 인가되지 않은 트래픽을 차단하지만, 위반 로그와 카운터를 통한 원인 확인은 제한적입니다.

---

### 3.2 Restrict 모드 — 차단 및 위반 기록

#### 예상 동작

- 인가되지 않은 출발지 MAC의 트래픽 폐기
- 위반 카운터 증가
- 인터페이스는 활성 상태 유지

#### 관찰 결과

- ICMP 통신 실패
- 위반 카운터 증가
- 인터페이스는 활성 상태 유지

#### 결론

Restrict 모드는 포트를 활성 상태로 유지하면서 인가되지 않은 트래픽을 차단하고, 위반 카운터를 통해 문제를 확인할 수 있도록 합니다.

---

### 3.3 Shutdown 모드 — 포트 비활성화: 기본 모드

#### 예상 동작

- 인터페이스가 `err-disabled` 상태로 전환
- 해당 포트의 모든 트래픽 차단
- 포트 복구 필요

#### 관찰 결과

- ICMP 통신 실패
- 위반 카운터 증가
- Gi0/1이 `err-disabled` 상태로 전환

#### 결론

Shutdown 모드는 위반 발생 시 포트 전체를 비활성화하므로, 해당 포트에 연결된 장비의 서비스가 즉시 중단됩니다.

> 자동 errdisable 복구를 별도로 구성하지 않은 경우 수동 복구가 필요합니다.

---

### 위반 모드 비교

| 모드 | 인가되지 않은 트래픽 | 위반 카운터 | 포트 상태 |
|---|---|---|---|
| Protect | 폐기 | 증가하지 않음 | 활성 상태 유지 |
| Restrict | 폐기 | 증가 | 활성 상태 유지 |
| Shutdown | 포트 전체 트래픽 차단 | 증가 | err-disabled |

이 테스트를 통해 보안 위반 처리 방식에 따라 장애 범위와 문제 확인 방법이 달라진다는 점을 확인했습니다.

---

## 4단계 — 포트 복구 및 문제 해결

### 상황

사용자가 갑작스러운 네트워크 연결 끊김을 보고한 상황을 가정했습니다.

### 수행 내용

- err-disabled 상태의 인터페이스 확인
- Gi0/1에서 `shutdown` 실행
- `no shutdown`으로 포트 복구 시도

```cisco
interface Gi0/1
 shutdown
 no shutdown
```

### 관찰 결과

- 인터페이스가 일시적으로 활성화되었습니다.
- 이후 다시 err-disabled 상태로 전환되었습니다.

### 근본 원인

- Linux-PC2에 인가되지 않은 MAC 주소가 계속 설정되어 있었습니다.
- 포트 보안 위반 모드가 Shutdown으로 유지되어 있었습니다.
- 복구 후에도 동일한 위반 조건이 남아 있어 차단이 다시 발생했습니다.

### 핵심 교훈

**보안 정책 위반의 원인을 해결하지 않고 포트만 복구하면 장애가 반복됩니다.**

복구 전에 단말의 MAC 주소와 포트의 보안 MAC 설정을 확인하고, 인가된 장비인지 판단한 후 원인을 해결해야 합니다.

---

## 핵심 학습 내용

이 실습에서는 장비 교체, 자리 이동, 의도하지 않은 MAC 주소 변경과 같은 상황에서 포트 보안이 통신에 미치는 영향을 확인했습니다.

Sticky MAC 학습은 MAC 주소를 자동으로 보안 설정에 등록할 수 있지만, 장비 변경 시 기존 보안 MAC 주소와 충돌할 수 있습니다.

Protect, Restrict, Shutdown 모드를 비교하면서 다음 사항을 배웠습니다.

- 위반 모드에 따라 트래픽 차단 범위와 로그 확인 가능 여부가 달라집니다.
- 포트 보안 설정은 사용자 서비스 가용성에 직접적인 영향을 줍니다.
- 포트 복구 전에는 위반 원인을 먼저 확인해야 합니다.
- 설정, 상태 정보, 실제 통신 결과를 함께 확인해야 문제를 정확히 판단할 수 있습니다.
