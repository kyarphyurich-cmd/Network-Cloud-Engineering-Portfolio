# WAN GRE over IPsec 실습

ISP 언더레이를 통한 안전한 오버레이 라우팅

## 프로젝트 개요

이 프로젝트에서는 **GRE over IPsec**을 활용하여 기업 환경을 모델로 한 **보안 WAN 구조**를 설계하고 구현한 후 동작을 검증합니다.

ISP 네트워크를 통해 본사(HQ)와 지사(Branch)를 연결하며, 전송 기반인 언더레이와 기업 내부 라우팅을 담당하는 오버레이를 분리합니다.

신뢰할 수 없는 WAN 구간에서 동적 라우팅을 사용하면서, 보호가 필요한 GRE 트래픽에 IPsec을 적용하는 것이 목표입니다.

OSPF 인접 관계는 GRE 오버레이에서만 형성하고, ISP 언더레이를 통과하는 GRE 트래픽은 IPsec으로 보호합니다.

---

## 설계 목표

- WAN 언더레이와 라우팅 오버레이의 역할 분리
- OSPF를 활용한 사이트 간 동적 라우팅 구현
- 언더레이를 단순하게 유지하면서 IPsec으로 오버레이 트래픽 보호
- 라우팅 프로토콜의 적용 범위와 보안 정책 명확화
- 제어 평면과 데이터 평면의 동작 검증

---

## 아키텍처 개요

이 설계는 언더레이와 오버레이로 구성됩니다.

### 언더레이 네트워크

언더레이는 ISP가 제공하는 **WAN 전송 기반**입니다.

각 사이트의 라우터와 ISP 라우터는 `/30` 지점 간 링크로 연결됩니다.

주요 특징은 다음과 같습니다.

- 정적 라우팅 사용
- ISP는 기업 OSPF에 참여하지 않음
- ISP 라우터에 기업 내부 LAN 경로를 구성하지 않음
- GRE 터널의 양 끝점 간 도달성 제공

### 오버레이 네트워크

오버레이는 HQ 라우터와 Branch 라우터 사이에 구성한 **GRE 가상 터널 인터페이스**입니다.

논리적인 지점 간 연결을 제공하며, 라우팅 프로토콜과 여러 내부 서브넷의 트래픽을 전달합니다.

주요 특징은 다음과 같습니다.

- GRE를 통한 내부 패킷 캡슐화
- 터널 인터페이스에서만 OSPF 인접 관계 형성
- 사이트 간 내부 LAN 경로의 동적 교환
- ISP 라우팅 영역과 기업 내부 라우팅 영역 분리

---

## 라우팅 전략

사이트 간 OSPF 경로 교환은 GRE 오버레이를 통해 이루어지도록 제한했습니다.

주요 설정 원칙은 다음과 같습니다.

- GRE 터널 및 LAN 인터페이스에만 OSPF 활성화
- 기본적으로 인터페이스를 passive 상태로 설정하고, GRE 터널만 인접 관계 형성을 허용
- WAN 또는 ISP 연결 인터페이스에서는 OSPF 인접 관계를 형성하지 않음
- LAN 인터페이스는 passive 상태로 유지하여 Hello 패킷 전송 없이 해당 네트워크를 광고

이를 통해 라우팅 동작을 예측하기 쉽게 만들고, ISP 네트워크와의 의도하지 않은 OSPF 상호작용을 방지합니다.

## 보안 설계

### GRE over IPsec

GRE는 캡슐화와 라우팅 유연성을 제공하지만, 자체적으로 암호화를 제공하지 않습니다.

따라서 IPsec을 함께 사용하여 다음 보안 기능을 제공합니다.

- **기밀성**: 전송 데이터 암호화
- **무결성**: 전송 중 데이터 변조 탐지
- **피어 인증**: 통신 상대 확인

### 암호화 범위

암호화 대상으로 터널 끝점 사이의 **GRE 트래픽**을 지정했습니다.

- GRE가 내부 LAN 트래픽과 OSPF 패킷을 캡슐화
- IPsec이 터널 모드로 GRE 패킷을 보호
- ISP 구간에서는 보호 대상 데이터가 ESP로 관찰됨
- 내부 IP 헤더, OSPF 정보 및 데이터 내용은 암호화된 내부에 포함됨

> 외부 IP 헤더의 터널 끝점 주소는 ISP 구간에서도 보입니다. 암호화로 보호되는 것은 내부 패킷과 GRE 헤더 등의 내용입니다.

이 방식으로 ISP의 라우팅 구성을 단순하게 유지하면서 사이트 간 오버레이 트래픽을 보호합니다.

## 검증 및 확인

IOS 상태 확인 명령어와 패킷 캡처를 함께 사용하여 동작을 검증했습니다.

### 터널 및 라우팅 검증

- GRE 터널 상태와 트래픽 카운터 확인
- GRE 터널을 통한 OSPF 인접 관계 확인
- OSPF로 학습한 내부 LAN 경로 확인
- 사이트 간 실제 통신 확인

### 보안 검증

- IKEv1/ISAKMP 1단계 SA 상태를 통해 피어 간 협상 상태 확인
- IPsec 2단계 SA 및 암호화 관련 카운터 확인
- 트래픽 발생 시 캡슐화 및 역캡슐화 카운터 증가 확인
- ISP 연결 구간에서 보호 대상 트래픽이 평문 GRE 대신 ESP로 전달되는지 확인

> ISP 링크 전체에 ESP만 존재한다는 의미는 아닙니다. ARP나 IKE 등 다른 트래픽이 함께 관찰될 수 있으므로, 실습의 보호 대상 트래픽을 기준으로 확인합니다.

## 실습을 통해 배운 점

### 1. 언더레이 도달성을 먼저 확보해야 함

GRE 터널을 구성하는 것만으로 원격 터널 끝점까지의 경로가 생성되지는 않습니다.

이 설계에서는 ISP 라우터를 통해 원격 터널 끝점에 도달하도록 정적 호스트 경로를 구성했습니다.

터널 상태 표시만으로 전체 통신 성공을 판단하지 않고, 끝점 도달성과 실제 트래픽 전달을 함께 확인해야 합니다.

### 2. 역할 분리가 설계와 문제 해결을 단순하게 만듦

언더레이는 터널 끝점 간 전송을 담당하고, 오버레이는 기업 내부 경로 교환을 담당하도록 분리했습니다.

이를 통해 문제가 발생했을 때 언더레이 도달성, GRE 전달, OSPF, IPsec을 순서대로 점검할 수 있었습니다.

### 3. 인터페이스 단위 OSPF 설정으로 적용 범위를 명확히 할 수 있음

넓은 범위의 network 명령어 대신, 필요한 인터페이스에 직접 OSPF를 활성화하여 적용 대상을 명확히 했습니다.

Passive 설정을 함께 사용하여 인접 관계가 형성되는 인터페이스도 제한했습니다.

### 4. 설정만큼 검증이 중요함

상태 확인 명령어와 Wireshark를 함께 사용하여 설계 의도대로 동작하는지 확인했습니다.

언더레이에서 보호 대상 트래픽이 평문 GRE 대신 ESP로 관찰되고, IPsec 카운터가 증가하는지 확인하여 암호화 적용을 검증했습니다.

### 5. GRE와 IPsec은 서로 다른 역할을 수행함

- **GRE**: 라우팅 프로토콜과 내부 트래픽의 캡슐화
- **IPsec**: 해당 트래픽의 암호화, 무결성 보호 및 피어 인증

두 기술을 결합하여 동적 라우팅을 지원하는 사이트 간 보안 연결을 구현했습니다.

## 핵심 정리

- 언더레이와 오버레이의 역할을 분리하면 WAN 구조를 명확하게 설계할 수 있습니다.
- GRE는 WAN을 통한 내부 트래픽 및 라우팅 프로토콜 전달을 지원합니다.
- IPsec은 GRE로 캡슐화한 트래픽을 보호합니다.
- OSPF의 활성화 범위와 인접 관계 형성 인터페이스를 제한해야 합니다.
- 상태 정보, 실제 통신, 패킷 캡처를 함께 확인해야 기능과 보안을 검증할 수 있습니다.

- OSPF 영역 설계를 고려한 경로 요약 및 경로 제어
- IPsec VTI 기반 설계와 비교
